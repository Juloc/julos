# JulOS 0.3.0-alpha.8

Release date: 2026-08-08

This alpha completes the production Desktop shell UX and lands the repository-side Browser profile, network-policy and session-orchestration foundation (BRW-002, BRW-003) on top of it.

## Added

- browser-native first-run administrator setup and local sign-in;
- enabled package applications compose into the existing launcher, window, taskbar and runtime stack, and verified package frontends serve through the authenticated desktop catalog;
- Core Settings, Package Manager, Agent status, notifications and problems ship as normal JulOS windows;
- signed package install, configure, enable, disable and remove flow, with the desktop catalog refreshing without a reload;
- persisted package widgets render through the existing widget host, and package window layout/state is restored and persisted;
- server-confirmed theme and motion preference changes apply immediately, without a reload;
- a reproducible builder and manual signing workflow for the official JulOS.HostMetrics, JulOS.Remote and JulOS.Browser packages;
- Browser package: persistent, temporary and application profile modes, user-bound profile ownership, and package-wide network profiles restricted to an administrator-allowlisted Runtime Manager network, with opaque proxy secret references;
- Browser package: the generic `interactive.session/1.0.0` capability, a bounded private package-worker command boundary, Runtime Manager-backed runtime allocation, HMAC-bound provider callbacks and terminal-session cleanup reusing the existing Remote session lifecycle worker.

## Known limitations

- creating a Browser profile or a network profile has no reachable caller yet; only reading an already-seeded profile during session creation is wired up ([issue #60](https://github.com/Juloc/julos/issues/60));
- the Core-side interactive-session orchestration (`InteractiveSessionCapabilityProvider`, `InteractiveSessionCleanupService`) has no automated test coverage yet, although the Browser worker's own command handling does ([issue #61](https://github.com/Juloc/julos/issues/61));
- deployed Browser provider/browser validation for BRW-003 (real internal-DNS and private-target evidence) remains outstanding, as does deployed Windows/macOS/touch acceptance for the Desktop UX.

## Upgrade from alpha.7

No Core schema change is introduced by this release. Keep the existing `JULOS_PRIMARY_KEY` and persistent volume, pull `ghcr.io/juloc/julos-server:0.3.0-alpha.8`, and recreate the server container.

No database edit or volume recreation is required.

## Docker evaluation

The recommended deployment remains `deploy/alpha/compose.sqlite.yaml`. It runs one JulOS server container with one persistent volume and no PostgreSQL service.

Required environment value:

- `JULOS_PRIMARY_KEY`: generate with `openssl rand -base64 32`.

The release Compose file binds to `127.0.0.1:8080` by default. The `Juloc/docker` deployment uses host port `18199`.

SQLite is intended for one JulOS server replica.
