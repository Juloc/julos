# JulOS 0.4.0-beta.24

Released 2026-08-31.

## Summary

Twenty-fourth JulOS beta. It fixes package workers staying dead after a host restart — which surfaced as "Package worker is unavailable" for interactive packages after a redeploy — and hides the local web browser app when the dynamic web-app proxy is not enabled. Only the server image is rebuilt; the official packages and runtime images are unchanged.

## Upgrade

| Question | Answer |
|---|---|
| Minimum previous version | `0.4.0-beta.23` |
| Database migration required | no |
| Downtime expected | brief restart |
| Safe mode required | no |

Pull the new server image and redeploy. Enabled package workers are now restarted automatically on startup, so no manual re-enable is required after an upgrade.

## Fixed

- **Enabled package workers were not restarted after a host restart.** Worker processes live in an in-memory supervisor that starts empty on boot, while package enablement is persisted in the database. After a restart or redeploy every enabled package stayed `Enabled` but its worker was dead, so any capability that invokes the worker — for example the interactive session the Adaptive Browser requires — failed with "Package worker is unavailable." The server now restarts the worker of every enabled package on startup (after the administrator-permission reconciliation), best-effort per package. Verified live by enabling a package, killing the server and its worker, restarting, and confirming the worker runs again on boot.
- **The local web browser app was offered even when the dynamic web-app proxy was disabled.** The Desktop now hides the local web browser application unless the web-app proxy is enabled, instead of presenting an app that cannot work (issue #95).

## Changed

- The server image is rebuilt at beta.24. Official packages, Runtime Manager (`0.4.0-beta.17`), the Remote Provider, the Browser Runtime and the Adaptive Browser images are unchanged.

## Known limitations

- Deployed rendered-display acceptance for RDP, VNC, SSH and Browser against the pinned provider image remains open (issues #37 / #41 / #43 / #45).

- Appearance personalization: a user-selectable accent, appearance presets and wallpaper/density controls are deferred (see DESK-016).
