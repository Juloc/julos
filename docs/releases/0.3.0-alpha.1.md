# JulOS 0.3.0-alpha.1

Release date: 2026-08-05

This is the first installable JulOS evaluation build. Its purpose is to validate product direction, interaction model, installation and the foundational package architecture before the remaining 1.0 packages are implemented.

## Included

- browser-based desktop shell with window management and persisted desktop state;
- initial administrator setup, session authentication and authorization foundations;
- global settings, package settings and core versioned APIs;
- package manifests, installation lifecycle, grants, capabilities, jobs and events;
- Agent registration, heartbeat, task orchestration and the current Linux metrics foundation;
- Remote session orchestration and policy foundations for RDP, VNC and SSH;
- protocol-neutral display transport and keyboard/resize handling;
- reproducible isolated Chromium runtime foundation;
- PostgreSQL migrations, readiness checks and a minimal alpha Compose deployment;
- immutable server image tag and automated prerelease publication.

## Known boundaries

- Docker and Proxmox packages are not implemented.
- Files and Caddy packages are not implemented.
- network discovery and final security hardening are not complete.
- Linux metrics still need validation on the intended deployed Debian host.
- RDP, VNC, SSH and Browser require provider-specific deployment configuration and real-device validation before they can be considered generally usable.
- package runtime workers are not bundled into the minimal control-plane Compose stack.
- Julgate migration and shutdown are not part of this alpha.
- the alpha is not supported for direct public internet exposure.

## Install

Use `deploy/alpha/compose.yaml` and follow `deploy/alpha/README.md`. The default endpoint is `http://127.0.0.1:8080`.

## Upgrade and rollback

The database schema may change between alpha releases. Create both a PostgreSQL dump and a protected copy of the external secret key ring before upgrading. Container rollback alone does not reverse database migrations.

## Validation

The release pipeline must pass the complete repository validator, build the server image, start the exact alpha Compose stack, complete database migration, pass the application readiness probe and then publish the immutable image and GitHub prerelease.
