# JulOS 0.3.0-alpha.2

Release date: 2026-08-05

This maintenance alpha fixes the container runtime problems found during the first real deployment of `0.3.0-alpha.1`.

## Fixed

- installs the GSSAPI runtime library required by Npgsql, removing the repeated `libgssapi_krb5.so.2` load error;
- stores ASP.NET Core Data Protection keys in a persistent internal Docker volume;
- encrypts persisted Data Protection XML with the existing JulOS primary key;
- removes the external secret-key directory and host-path requirement;
- accepts `JULOS_PRIMARY_KEY` directly from `.env` through a Docker Compose secret;
- verifies the dependency, encrypted key file, restart persistence and absence of the known warnings in the release smoke test.

## Install

Use the attached Compose file and environment example. Set only the required PostgreSQL password and JulOS primary key, then start the stack with Docker Compose.

The default endpoint is `http://127.0.0.1:8080`.

## Upgrade from alpha.1

1. Back up PostgreSQL.
2. Keep the same primary key value that was stored in `primary.key` and place that value in `JULOS_PRIMARY_KEY`.
3. Replace the Compose file and environment example.
4. Change the server image to `ghcr.io/juloc/julos-server:0.3.0-alpha.2`.
5. Run `docker compose pull` followed by `docker compose up -d`.

The old external key directory is no longer mounted. The database remains unchanged and the migration service still runs before the server.

## Alpha boundaries

Docker, Proxmox, Files, Caddy, discovery, final production hardening and Julgate migration remain outside this alpha. Remote providers and Browser runtime still require environment-specific deployment configuration and validation.
