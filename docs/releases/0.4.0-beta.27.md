# JulOS 0.4.0-beta.27

Released 2026-09-01.

## Summary

Twenty-seventh JulOS beta. Two mobile follow-ups to the iPad-style dock from `0.4.0-beta.26`: app content no longer hides behind the floating dock, and Local Web gains an "open in a new tab" escape hatch for internal apps that are cramped or broken inside the in-shell iframe. Frontend-only; the server image is rebuilt to carry the new Desktop bundle. No package, runtime or provider images change.

## Upgrade

| Question | Answer |
|---|---|
| Minimum previous version | `0.4.0-beta.26` |
| Database migration required | no |
| Downtime expected | brief restart |
| Safe mode required | no |

Pull the new server image and redeploy. Hard-refresh the browser (or reopen the installed PWA) once so the updated shell assets load.

## Changed

- **Mobile app content clears the floating dock.** On phone-class viewports the desktop content area now reserves the dock's real footprint (pill height + a small gap + its bottom offset, tracking `env(safe-area-inset-bottom)` so it is correct on phones with a home indicator). App windows, widgets and core views end just above the dock instead of being covered by it. This closes the known limitation noted in `0.4.0-beta.26`.
- **Local Web can open the current app in a new tab.** A new "open in a new tab" (↗) button sits next to Open. It opens the current proxied URL — reachable through the JulOS proxy zone — full-screen in the real browser, so an internal web app that is cramped or renders poorly inside the in-shell sandboxed iframe can be used at full size, especially on mobile.

## Known limitations

- The mobile dock is always visible (it no longer overlaps content, but does not yet auto-hide per-app the way iPadOS does).
- Deployed rendered-display acceptance for RDP, VNC, SSH and Browser against the pinned provider image remains open (issues #37 / #41 / #43 / #45).
- Remaining WEB-001 work: body/reference rewriting, the runtime shim, Agent-tunnel reachability, server-side credential injection and the `auto` streamed fallback.
- Appearance personalization: a user-selectable accent, appearance presets and wallpaper/density controls are deferred (see DESK-016).
