# JulOS 0.4.0-beta.8

Eighth JulOS beta. It makes official package builds byte-reproducible and publishes the Browser profile/tabs/fixed-app features through the faster release pipeline. It supersedes the incomplete `0.4.0-beta.5` and `0.4.0-beta.7` publishes.

## Fixed

- Official package artifacts are now byte-reproducible across releases. `tools/build-package-artifact.sh` no longer lets the .NET SDK embed the building git commit into the worker assemblies' informational version (`-p:IncludeSourceRevisionInInformationalVersion=false`), so rebuilding an unchanged package produces identical bytes. Previously each rebuild embedded a different commit, so re-running a release tripped the package byte-immutability guard (it did on `0.4.0-beta.7`). The whole worker publish output — worker, Package SDK and Contracts assemblies and `deps.json` — was verified byte-identical across differing commits.

## Changed

- All three official packages advance to `1.0.3`. This is the same functionality as `1.0.2`, rebuilt reproducibly; the `1.0.2` bytes were tied to the commit that built them and cannot be reproduced, so a fresh reproducible version is published.
- The release pipeline runs validation as five parallel jobs and builds `linux/amd64`-only images with per-image Docker layer caches (introduced in the Beta5–Beta7 line), cutting release wall-clock without reducing coverage.

## Application features (carried from the Beta5–Beta7 line)

- Browser profile selector and in-app "New profile" creation through the generic `interactive.profiles/1.0.0` capability.
- Multi-session tabs in the Browser app; switching detaches and re-attaches the display, background sessions persist under the server idle timeout, and closing a tab terminates its session.
- Fixed web-application mode: a saved application target opens in minimal app chrome around the same full interactive browser session (not an iframe), with a "Full browser" control.

## Deployment

The server image for this prerelease is:

`ghcr.io/juloc/julos-server:0.4.0-beta.8`

Do not deploy `0.4.0-beta.5` or `0.4.0-beta.7`: their publishes did not complete. Use `0.4.0-beta.8` (or `0.4.0-beta.6`, which is complete but ships packages `1.0.2`).

Existing data and keys remain compatible. Preserve `JULOS_PRIMARY_KEY`, `JULOS_RUNTIME_MANAGER_KEY` and `JULOS_REMOTE_PROVIDER_CALLBACK_KEY` when upgrading. After redeploying, open the JulOS package catalog and update the installed Browser, Remote and Host Metrics packages to `1.0.3`; configuration and enabled state are preserved.

Runtime images are unchanged and remain digest-pinned:

- Browser runtime: `ghcr.io/juloc/julos-browser-runtime@sha256:933a2a8b7bc260560d0c2459ca8aa102596ab282bb094eb690c5ecf767302a8a`
- Remote provider: `ghcr.io/juloc/julos-remote-provider@sha256:e9c9d61adb82e56370a5fdaa76344dab686b4afd90a2ce41fc82cfe3a510b643`

## Security boundary

Unchanged: no Docker socket in Server, immutable digest-pinned runtimes, Runtime Manager as the only Docker control plane, allowlisted runtime networks. No credential, target or trust policy is widened.

## Validation focus

- an unchanged official package rebuilds to identical bytes on a later release run
- the split parallel validation reproduces the previous single-job coverage
- the published server image is single-architecture `linux/amd64`
- Browser, Remote and Host Metrics update to `1.0.3` preserving configuration and enabled state
