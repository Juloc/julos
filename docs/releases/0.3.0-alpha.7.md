# JulOS 0.3.0-alpha.7

Release date: 2026-08-07

This alpha fixes the production browser entry point that returned the JulOS API `request_not_found` problem response at `/` in `0.3.0-alpha.6` even though the Server itself was healthy.

## Fixed

- the Desktop build is copied into `JulOS.Server/wwwroot` before `dotnet publish`, so ASP.NET Core publishes and serves the same static web assets that the container contains;
- `GET /` now serves the JulOS Desktop shell instead of falling through to the API 404 endpoint;
- the release smoke test now requires `/` to contain the JulOS HTML title and requires `/scripts/main.js` to be served successfully;
- the separate runtime-stage Desktop copy was removed so there is only one authoritative web-root delivery path;
- both alpha Compose variants reference `0.3.0-alpha.7`.

## Upgrade from alpha.6

No Core schema change is introduced by this release. Keep the existing `JULOS_PRIMARY_KEY` and persistent volume, pull `ghcr.io/juloc/julos-server:0.3.0-alpha.7`, and recreate the server container.

No database edit or volume recreation is required.

## Docker evaluation

The recommended deployment remains `deploy/alpha/compose.sqlite.yaml`. It runs one JulOS server container with one persistent volume and no PostgreSQL service.

Required environment value:

- `JULOS_PRIMARY_KEY`: generate with `openssl rand -base64 32`.

The release Compose file binds to `127.0.0.1:8080` by default. The `Juloc/docker` deployment uses host port `18199`.

SQLite is intended for one JulOS server replica.
