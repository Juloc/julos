# JulOS 0.4.0-beta.32

Released 2026-09-05.

## Summary

Thirty-second JulOS beta. Browser is now a single proxy-first Core application. The old Browser and
Adaptive Browser packages, isolated Chromium runtimes, provider, workers, release jobs and store
entries are removed. Public websites can use the JulOS proxy with pinned-DNS SSRF protection, while
private networks remain explicitly allowlisted. This release also includes the mobile window-chrome
fix and persistent 48-hour login sessions with renewal on JulOS startup.

## Upgrade

| Question | Answer |
|---|---|
| Minimum previous version | `0.4.0-beta.31` |
| Database migration required | no |
| Downtime expected | brief restart |
| Safe mode required | no |

Pull the new server image and redeploy. Existing installed legacy Browser/Adaptive Browser package
data is no longer used by the product and the official package catalog no longer publishes those
packages.

## Changed

- **One Browser only.** The Core Browser uses JulOS transparent proxy rendering. Legacy Browser and
  Adaptive Browser packages/runtimes were removed rather than kept as hidden alternatives.
- **Public-web proxy mode.** Public Internet destinations are allowed through DNS resolution and
  address pinning. Private, loopback and link-local destinations remain blocked unless explicitly
  allowed by the deployment policy.
- **Browser compatibility path simplified.** HTTP/HTTPS, WebSocket pass-through, framing/CSP handling,
  cookie handling and redirects remain proxy responsibilities. There is no remote-browser fallback.
- **Login persistence.** Login/setup now issue persistent root-scoped sessions. The default lifetime
  is 48 hours with sliding renewal, and Desktop startup refreshes an authenticated session.
- **Mobile window chrome.** Phone/mobile always uses compact JulOS window controls rather than
  inheriting macOS-style controls from iPhone/iPad platform identification.
- **Taskbar/window work area.** Desktop window chrome and taskbar usable-area calculations are aligned.

## Known limitations

- Transparent proxy rendering cannot guarantee compatibility with every site that hard-codes its
  original origin, uses incompatible OAuth/origin checks, or depends on browser-local state that
  cannot be transparently proxied.
- Cross-device Browser tabs/workspace persistence is the next Browser work item and is not yet
  complete in this build.
- Deployed rendered-display acceptance for RDP, VNC and SSH remains separate Remote work.
