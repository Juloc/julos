# JulOS 0.3.0-alpha.9

Release date: 2026-08-08

This alpha fixes first-run administrator setup on the SQLite evaluation deployment, which a real deployment check of `0.3.0-alpha.8` found completely broken.

## Fixed

- `InitialAdministratorProvisioner.CreateAsync` issued a raw `SELECT ... FOR UPDATE` query unconditionally; `FOR UPDATE` is PostgreSQL-only syntax that SQLite rejects with a syntax error, so `POST /api/v1/auth/setup` always failed with HTTP 500 on every SQLite deployment;
- the query now branches on the configured provider: SQLite reads the setup row through the normal tracked query, PostgreSQL keeps the existing row-locking `FOR UPDATE` read;
- a new SQLite integration test drives the real HTTP host through `/api/v1/auth/setup` end to end and fails without the fix;
- `deploy/alpha/.env.sqlite.example` and `deploy/alpha/.env.example` pinned `JULOS_SERVER_IMAGE` to `0.3.0-alpha.4` and `0.3.0-alpha.2` respectively and were never updated by later releases, so following the documented quick-start literally silently pulled a stale image; both now reference `0.3.0-alpha.9`, and the unused `JULOS_VERSION` variable was removed from the PostgreSQL example.

## Upgrade from alpha.8

No Core schema change is introduced by this release. Keep the existing `JULOS_PRIMARY_KEY` and persistent volume, pull `ghcr.io/juloc/julos-server:0.3.0-alpha.9`, and recreate the server container.

If `0.3.0-alpha.8` never completed first-run setup, no volume recreation is required: recreating the container with the fixed image against the existing empty volume completes setup normally.

## Docker evaluation

The recommended deployment remains `deploy/alpha/compose.sqlite.yaml`. It runs one JulOS server container with one persistent volume and no PostgreSQL service.

Required environment value:

- `JULOS_PRIMARY_KEY`: generate with `openssl rand -base64 32`.

The release Compose file binds to `127.0.0.1:8080` by default. The `Juloc/docker` deployment uses host port `18199`.

SQLite is intended for one JulOS server replica.
