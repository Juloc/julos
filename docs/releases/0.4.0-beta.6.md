# JulOS 0.4.0-beta.6

Sixth JulOS beta. It ships the Browser package's in-app profile management, tabbed sessions and fixed web-application mode, and supersedes an incomplete `0.4.0-beta.5` publish.

## Added

- The Browser package (`1.0.2`) gains an in-app profile experience: a toolbar profile selector that lists the signed-in user's retained profiles and starts the session with the chosen profile (temporary by default), and a "New profile" form that creates a persistent profile against a configured network profile.
- A new generic `interactive.profiles/1.0.0` capability backs this. The Browser worker owns create/list/delete for profiles and network profiles; a product-neutral Core provider forwards the opaque package request to the caller's own worker with the trusted owning user. Profile ownership, the administrator network allowlist and secret-reference opacity are enforced, and proxy secret references are never returned.
- The Browser application runs multiple independent sessions in a tab bar. Each tab owns its own interactive session; switching detaches and re-attaches the display (background sessions persist under the server idle timeout) and closing a tab terminates its session.
- Fixed web-application mode: launching the Browser from a saved application target renders minimal app chrome — the address bar, tab bar and profile controls are hidden around the same full interactive browser session, not an iframe — with a "Full browser" control that reveals the complete chrome.

## Changed

- All three official packages advance to `1.0.2`. The Browser worker and frontend changed for the features above; the Remote and Host Metrics workers are byte-different rebuilds because they bundle the shared Package SDK, which gained the `interactive.profiles` contracts this cycle. Their behavior is unchanged. An immutable package version always identifies immutable bytes, so a byte change requires a new version.
- Release images are built for `linux/amd64` only. JulOS targets amd64; the previously produced (and unused) arm64 image variants are dropped, which also shortens the release build.

## Fixed and tested

- The Desktop shell (`JulOsShell`) gains JSDOM regression coverage for authenticated-name persistence through the `#applyLanguage()` sweep and for `onProfileChanged` reapplying theme/motion after a Core Settings save. Both defects had previously only been caught by manual deployed testing.
- A new `browser-frontend-test` validation stage covers the Browser frontend's pure logic: session-request mapping, profile/network list validation, tab title and post-close activation, chrome-mode resolution and HTML escaping.

## Deployment

The server image for this prerelease is:

`ghcr.io/juloc/julos-server:0.4.0-beta.6`

Do not deploy `0.4.0-beta.5`: its publish did not complete and its embedded packages carry inconsistent versions. Use `0.4.0-beta.6`.

Existing Beta4 data and keys remain compatible. Preserve `JULOS_PRIMARY_KEY`, `JULOS_RUNTIME_MANAGER_KEY` and `JULOS_REMOTE_PROVIDER_CALLBACK_KEY` when upgrading.

After redeploying the Beta6 server, open the JulOS package catalog and update the installed Browser, Remote and Host Metrics packages from `1.0.1` to `1.0.2`. Package updates remain operator-controlled; JulOS does not silently replace installed packages during server startup. Existing package configuration and enabled state are preserved by the normal update path.

Runtime images are unchanged and remain digest-pinned:

- Browser runtime: `ghcr.io/juloc/julos-browser-runtime@sha256:933a2a8b7bc260560d0c2459ca8aa102596ab282bb094eb690c5ecf767302a8a`
- Remote provider: `ghcr.io/juloc/julos-remote-provider@sha256:e9c9d61adb82e56370a5fdaa76344dab686b4afd90a2ce41fc82cfe3a510b643`

## Security boundary

Unchanged: the JulOS Server still has no Docker socket, runtime images remain immutable and digest-pinned, Runtime Manager remains the only Docker control-plane component, and runtime networks remain allowlisted. The new `interactive.profiles` capability forwards only opaque package payloads together with the trusted user identity, and never returns secret references.

## Validation focus

- Browser profile create, select and delete through `interactive.profiles`
- tabbed sessions switch, persist in the background and clean up on close
- fixed web-application mode shows minimal chrome and can expand to the full browser
- Browser, Remote and Host Metrics update from `1.0.1` to `1.0.2` while preserving configuration and enabled state
