# JulOS 0.4.0-beta.23

Released 2026-08-31.

## Summary

JulOS 0.4.0-beta.23 adds the independent Adaptive Browser package. It keeps the existing Browser package and Local Web surface unchanged while adding selectable device or isolated JulOS-server rendering.

## Upgrade

| Question | Answer |
|---|---|
| Minimum previous version | `0.4.0-beta.21` |
| Database migration required | no |
| Downtime expected | brief restart |
| Safe mode required | no |

Pull the beta.23 server image and redeploy. Adaptive Browser server mode additionally requires the digest-pinned Adaptive Browser provider in the Remote provider configuration and port `8080` in the selected Remote network profile.

## Added

- **Adaptive Browser `0.1.0`** as an additional official package.
- `Automatic`, `This device` and `JulOS server` execution choices.
- Device rendering using the user's browser and GPU capabilities when normal browser framing policy permits it.
- Isolated headless Chromium server sessions through the existing `interactive.session/1.0.0` boundary.
- Authenticated `julos-browser-stream.v1` presentation over the existing same-origin Remote display gateway without VNC, noVNC or Guacamole.
- Navigation, back/forward, reload/stop, viewport resize, pointer, wheel and keyboard controls.
- Independent tab/session state per server-rendered tab.
- Dedicated immutable Adaptive Browser Runtime and Provider images with publication attestations.

## Security and isolation

- The browser never receives a raw Chrome DevTools endpoint or runtime credential.
- Runtime and provider images are immutable and digest-pinned at deployment/catalog boundaries.
- Network and target policy remains server-side; the client execution preference cannot expand access.
- Forced device mode never silently falls back to server execution.

## Validation

The merged implementation passed the complete repository validator, including 546 .NET tests, Desktop and package frontend tests, package manifest integrity, the real Adaptive Browser container smoke test and clean-tree verification. The container smoke covers authenticated browser-stream transport, invalid authentication/subprotocol rejection, raw-CDP rejection, Chromium page loading, SwiftShader WebGL and receipt of a screencast frame.

## Known limitations

- Device mode is still subject to normal CSP, `X-Frame-Options` and same-origin framing restrictions.
- Browser-stream audio, file uploads, downloads and clipboard synchronization are not part of the first version.
- Server rendering uses SwiftShader as the portable WebGL baseline; hardware GPU passthrough remains an explicit Runtime Manager policy feature.
