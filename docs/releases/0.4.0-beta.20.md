# JulOS 0.4.0-beta.20

Released 2026-08-26.

## Summary

Twentieth JulOS beta. It fixes an authorization defect that left an existing administrator without any permission added to the catalog after the initial setup completed. After an upgrade this made administrator-only actions fail silently with 403 — most visibly package install, enable, disable and remove, and the local web-app proxy ("Local web-app mode is not enabled"). Only the server image is rebuilt; the official packages stay at `1.0.4` and the runtime images are unchanged.

Pull the new server image and redeploy. On startup the server now reconciles the administrator role with the current permission catalog, so no manual grant or configuration change is required.

## Fixed

- **An administrator provisioned on an earlier version never received permissions added later, so guarded actions returned 403 after an upgrade.** The initial-administrator provisioner seeds permission grants exactly once, while the first administrator is created. Any permission introduced afterwards — for example `core.webapp.use` (added when the local web-app proxy was gated) or a package lifecycle permission on an older install — never reached an already-existing administrator role. Authorization then rejected the request before the handler ran, so package install/enable/disable/remove and the web-app proxy did nothing, no server error was logged, and the database never changed. The server now runs a startup reconciliation that grants the administrator role any missing catalog permission. It is best-effort (an unreachable database at startup cannot stop the host) and idempotent (only missing grants are added), and it is covered by an integration test that proves a de-permissioned administrator is forbidden and then reinstated.
