# JulOS 0.4.0-beta.19

Released 2026-08-25.

## Summary

Nineteenth JulOS beta. It fixes a routing defect that made package management partly unusable in the deployed server: packages could be installed but not uninstalled, enabled or disabled. Only the server image is rebuilt; the official packages stay at `1.0.4` and the runtime images are unchanged.

| Question | Answer |

Pull the new server image and redeploy. No package or configuration change is required.

## Fixed

- **Package uninstall, enable, disable and update returned 404 in the deployed server.** A routed catch-all fallback (`MapFallback` with `{*path:nonfile}`) suppressed the `{packageId}` parameter action routes in the endpoint table under Kestrel — `DELETE /api/v1/packages/{id}`, `POST /{id}/enable`, `POST /{id}/disable`, `POST /{id}/update` and `POST /{id}/update-preview` — so packages could be installed but never removed, enabled or disabled. It is replaced with a no-endpoint 404 middleware that preserves the JulOS `request.not_found` response and the web-application proxy. The in-memory test host did not reproduce this, so a new `server-smoke` validation stage boots the real Kestrel server and asserts these routes are reachable.

## Changed

- The server image is rebuilt at beta.19. Official packages remain at `1.0.4`; Runtime Manager (`0.4.0-beta.17`), the Remote Provider (`dc0960ca…`) and the Browser Runtime (`14ecfacb…`) are unchanged.
- CI runs a real-host `server-smoke` routing check on every pull request and in the release validation.

## Known limitations

- Deployed rendered-display acceptance for RDP, VNC, SSH and Browser against the pinned provider image remains open (issues #37 / #41 / #43 / #45).
- Remaining WEB-001 work: body/reference rewriting, the runtime shim, Agent-tunnel reachability, server-side credential injection and the `auto` streamed fallback.
- Appearance personalization: a user-selectable accent, appearance presets and wallpaper/density controls are deferred (see DESK-016).
