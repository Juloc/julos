# JulOS 0.3.0-alpha.10

Release date: 2026-08-08

This alpha fixes the authenticated user's display name, found while completing the real deployment check of `0.3.0-alpha.9`.

## Fixed

- `#loadSession()` set the signed-in user's display name onto the settings-button label, but the element still carried the static `data-message="loading"` placeholder attribute; the very next `#applyLanguage()` call (run immediately afterward, and again on any later language or profile refresh) swept every `[data-message]` element and overwrote the real name back to the translated "Loading" placeholder;
- the display name now clears that placeholder attribute once real content is set, so it survives subsequent language and profile refreshes;
- issue [#62](https://github.com/Juloc/julos/issues/62) tracks adding dedicated `shell.ts` test coverage so this class of regression is caught automatically instead of only by manual/deployed testing.

## Upgrade from alpha.9

No Core schema change is introduced by this release. Keep the existing `JULOS_PRIMARY_KEY` and persistent volume, pull `ghcr.io/juloc/julos-server:0.3.0-alpha.10`, and recreate the server container.

No database edit or volume recreation is required.

## Docker evaluation

The recommended deployment remains `deploy/alpha/compose.sqlite.yaml`. It runs one JulOS server container with one persistent volume and no PostgreSQL service.

Required environment value:

- `JULOS_PRIMARY_KEY`: generate with `openssl rand -base64 32`.

The release Compose file binds to `127.0.0.1:8080` by default. The `Juloc/docker` deployment uses host port `18199`.

SQLite is intended for one JulOS server replica.
