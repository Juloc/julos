# JulOS 0.4.0-beta.33

Released 2026-09-05.

## Summary

Thirty-third JulOS beta. Fixes Browser proxy navigation escaping to the original site when an
upstream redirects to a different HTTP/HTTPS origin.

For example, `https://test.de` redirects to `https://www.test.de/`. Previously JulOS forwarded
that cross-origin `Location` unchanged, so the iframe loaded `www.test.de` directly and the site's
`X-Frame-Options: DENY` blocked rendering. Cross-origin redirects are now encoded back into the
JulOS dynamic proxy zone.

Pull the new server image and redeploy.

## Fixed

- Absolute HTTP/HTTPS redirects to a different origin no longer escape the JulOS Browser proxy.
- Same-origin redirects keep using the current encoded proxy host.
- Sites such as `test.de` that canonicalize to a `www` hostname remain inside JulOS, so JulOS can
  continue removing `X-Frame-Options` and incompatible `frame-ancestors` directives.

## Known limitations

- This fix covers HTTP redirect headers. Arbitrary URLs created later by page JavaScript or absolute
  third-party asset URLs are a separate proxy-compatibility problem and may still leave the encoded
  origin unless rewritten by a future compatibility layer.
- Cross-device Browser workspace persistence is not yet complete.
