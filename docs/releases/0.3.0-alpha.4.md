# JulOS 0.3.0-alpha.4

Release date: 2026-08-07

This alpha is the corrected Docker evaluation release after real container lifecycle testing of the Browser runtime and the SQLite single-service server profile.

## Fixed

- the SQLite database now lives below the writable persistent data directory at `/var/lib/julos/data/julos.db`;
- the server image pre-creates `data`, `packages` and `data-protection` with the non-root runtime user's ownership before Docker initializes a named volume;
- the release smoke test starts the exact single-service SQLite Compose stack, verifies readiness and persisted directories, restarts the server and verifies readiness again;
- SQLite process package workers are enabled and receive their own isolated package database connections;
- PostgreSQL package workers keep their restricted per-package role and schema behavior;
- Browser Runtime health checks use the launcher's `/tmp/julos-browser` state directory;
- Openbox starts through the `DISPLAY` environment supported by Debian Bookworm;
- Browser Runtime failures expose Xvfb, Openbox, x11vnc and Chromium diagnostics;
- Server, Browser Runtime and Remote Transport publication workflows publish trusted versions from `main`.

## Docker evaluation

The recommended evaluation deployment is `deploy/alpha/compose.sqlite.yaml`. It runs one JulOS server container, requires no PostgreSQL service and persists its state in one named volume.

Required environment value:

- `JULOS_PRIMARY_KEY`: generate with `openssl rand -base64 32`.

The release Compose file binds to `127.0.0.1:8080` by default. The `Juloc/docker` deployment uses host port `18199`.

SQLite is intended for one JulOS server replica. PostgreSQL remains available for deployments that require it.

## Released components

- `ghcr.io/juloc/julos-server:0.3.0-alpha.4`
- `ghcr.io/juloc/julos-browser-runtime:0.3.0-alpha.4`
- `JulOS.Remote.Transport` `0.3.0-alpha.4`

The Browser Runtime image is an internal JulOS runtime and does not need a separately exposed host port. Full Browser container sessions and deployed Remote-provider sessions still require their Runtime Manager/provider environment; the single-service stack covers the JulOS shell, setup, settings, package platform and process package workers.
