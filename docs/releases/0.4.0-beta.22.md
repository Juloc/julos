# JulOS 0.4.0-beta.22

Released 2026-08-30.

## Summary

Twenty-second JulOS beta. It fixes two Remote-session failure modes found while debugging deployed RDP: provider bootstrap failures can no longer be rejected because they use provider-private diagnostic codes, and `remote.session/create` no longer keeps the browser request open while Runtime Manager pulls or starts the provider image. Remote provisioning now continues from durable database state in a background worker. This release also includes the PWA and Local Web work merged after beta.21. Official packages remain at `1.0.4`; Runtime Manager and Remote/Browser runtime images are unchanged.

## Fixed

- **Remote sessions could remain stuck after a provider bootstrap failure.** Provider runtimes emit internal diagnostics such as `remote.provider_webapp_unavailable`. Those codes previously reached the durable session boundary directly and could be rejected as unsupported public failure codes, leaving the session in a non-terminal state. The authenticated provider callback endpoint now normalizes the private bootstrap family to caller-safe `remote.runtime_unavailable` before mutating the session.
- **Creating a Remote/RDP session could block the browser request on runtime creation or a first image pull.** `remote.session/create` now persists and immediately returns the authoritative `requested` session. A background provisioning worker reads pending state from the core database and performs the existing idempotent Runtime Manager allocation independently of the initiating browser request.
- **Interrupted Remote provisioning now survives a Server restart.** At startup the worker reconciles persisted `requested` and `provisioning` sessions and reuses the stable `remote-{sessionId}` runtime identity, so recovery does not depend on an in-memory queue or require the browser to create a second session.

## Changed

- Remote creation now exposes the documented durable lifecycle to the frontend: `requested` → `provisioning` → `connecting` → `connected` or a terminal state.
- The process-local provisioning signal carries no session data and is only a latency optimization; the core database remains authoritative.
- The server image includes the installable-PWA shell work and the Local Web naming/compatibility updates merged after beta.21.
- Official packages remain at `1.0.4`; Runtime Manager (`0.4.0-beta.17`), the Remote Provider (`dc0960ca…`) and the Browser Runtime (`14ecfacb…`) are unchanged.

## Known limitations

- Deployed rendered-display acceptance for RDP, VNC, SSH and Browser against the pinned provider image remains open until beta.22 is exercised through a newly created real session.
- The Remote frontend currently polls pending creation for a bounded period; an unusually slow provider startup can require an explicit reconnect/read after that UI window even though durable server-side provisioning continues.
- Remaining WEB-001 and later Host Connector/mobile work stays tracked in the backlog.
