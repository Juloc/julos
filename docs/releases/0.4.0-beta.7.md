# JulOS 0.4.0-beta.7

Seventh JulOS beta. It carries no functional changes over `0.4.0-beta.5`/`0.4.0-beta.6`; it exists to publish the same application through a faster release pipeline and to confirm that pipeline end to end.

## Changed

- The release pipeline is faster with no loss of rigor. Repository validation is split into five parallel jobs (`.NET` incl. PostgreSQL integration tests, Desktop, package frontends, metadata, container build), so wall-clock is the slowest job rather than the sum of every stage. Release images build for `linux/amd64` only (JulOS targets amd64), and the Browser runtime, Runtime Manager and Remote provider image builds gained a per-image Docker layer cache. The full test suite, the container build, package signing and attestation, and the byte-immutability guards are all unchanged.
- Pure-logic test assemblies (`Domain`, `Architecture`, `Remote.Transport`) run their classes in parallel; the integration suite stays serial by design.

## Packages

The three official packages remain `1.0.2` with byte-identical artifacts to `0.4.0-beta.6`; there is nothing to update if you already installed the Beta6 `1.0.2` packages.

## Deployment

The server image for this prerelease is:

`ghcr.io/juloc/julos-server:0.4.0-beta.7`

Existing Beta6 data, keys and installed `1.0.2` packages remain compatible. Preserve `JULOS_PRIMARY_KEY`, `JULOS_RUNTIME_MANAGER_KEY` and `JULOS_REMOTE_PROVIDER_CALLBACK_KEY` when upgrading. Runtime images remain digest-pinned and unchanged:

- Browser runtime: `ghcr.io/juloc/julos-browser-runtime@sha256:933a2a8b7bc260560d0c2459ca8aa102596ab282bb094eb690c5ecf767302a8a`
- Remote provider: `ghcr.io/juloc/julos-remote-provider@sha256:e9c9d61adb82e56370a5fdaa76344dab686b4afd90a2ce41fc82cfe3a510b643`

## Security boundary

Unchanged: no Docker socket in Server, immutable digest-pinned runtimes, Runtime Manager as the only Docker control plane, allowlisted runtime networks. No credential, target or trust policy is widened.

## Validation focus

- the split parallel validation reproduces the same coverage as the previous single-job validator
- the published server image is single-architecture `linux/amd64`
- the official packages remain byte-identical `1.0.2`
