# JulOS 0.4.0-beta.15

Fifteenth JulOS beta. This prerelease carries the complete Remote provider tunnel-authentication correction found during deployed Browser validation.

## Changed

- Remote Provider exchanges encrypted Guacamole JSON-auth `data` through `/api/tokens` and uses only the returned `authToken` for the private WebSocket tunnel.
- The private nginx-to-Guacamole tunnel now also supplies the required `GUAC_DATA_SOURCE=json`, `GUAC_ID=<session ID>` and `GUAC_TYPE=c` selectors, so Guacamole starts the exact per-session JSON connection instead of only exchanging keepalive traffic.
- Provider `connected` is reported only after the Guacamole web application, authentication exchange and nginx listener are ready.
- Regression coverage rejects the previous token-only tunnel shape.
- Docker/network topology and browser-facing Remote contracts are unchanged.

## Publication

For the Remote display re-test, publish the session runtimes from `main` with the Release workflow target `session-runtimes`. This creates immutable `0.4.0-beta.15` Runtime Manager and Remote Provider images.

After publication, pin the emitted Remote Provider digest in `deploy/compose/compose.remote.yaml` before deployed validation. Do not reuse the previous provider container or digest as evidence for this fix.

The three official packages remain at `1.0.3` and the Browser runtime is unchanged.

## Validation focus

- create a new Browser/Remote session using the newly published and digest-pinned provider image
- require Guacamole protocol/display instructions beyond keepalive `ping`
- confirm Chromium actually renders inside the JulOS window
- then repeat RDP, VNC, SSH and browser/Android Remote display acceptance
