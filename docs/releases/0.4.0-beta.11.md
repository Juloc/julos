# JulOS 0.4.0-beta.11

Eleventh JulOS beta. It stops an unhandled 500 when saving a desktop layout and keeps the layout persisting. It changes only the Server; the official packages are byte-identical to `0.4.0-beta.8`.

## Fixed

- Saving a desktop layout no longer fails with an unhandled 500. When window z-indexes had a gap — which the client can produce, for example after a window in the middle closes — the layout save threw an unhandled `ArgumentException` that surfaced as a 500 and the layout was not persisted, spamming the logs on every window open or close. The Server now normalizes the surviving windows into a dense `0..N-1` stacking order on save instead of rejecting gaps, and answers `400` rather than `500` for a genuinely malformed layout. Window-id and z-index uniqueness and non-negativity are still enforced.

## Carried from the 0.4.0-beta.9/10 line

- The Browser (`interactive.session`) display descriptor is issued on `read` once a session is connected and is always bound to the session's current revision, so the Browser reliably attaches its remote canvas (`0.4.0-beta.10`).
- The alpha PostgreSQL compose runs the full migrate invocation, and the dev remote compose pins the runtime network name `julos-remote`.

## Changed

- The three official packages remain at `1.0.3`. This release changes only the Server; the package artifacts (Browser, Remote and Host Metrics) are byte-identical to `0.4.0-beta.8` and are not re-published.

## Deployment

The server image for this prerelease is:

`ghcr.io/juloc/julos-server:0.4.0-beta.11`

Existing data and keys remain compatible. Preserve `JULOS_PRIMARY_KEY`, `JULOS_RUNTIME_MANAGER_KEY` and `JULOS_REMOTE_PROVIDER_CALLBACK_KEY` when upgrading. The installed Browser, Remote and Host Metrics packages stay at `1.0.3`; no package update is required.

Operational note: the first interactive session after a fresh deploy pulls the runtime images (Browser runtime and Remote provider, ~1.3 GB and ~1.8 GB). Until they are cached, that first session can exceed the create timeout and fail to connect; pre-pull the digest-pinned runtime images on the host to make the first session connect promptly.

Runtime images are unchanged and remain digest-pinned:

- Browser runtime: `ghcr.io/juloc/julos-browser-runtime@sha256:933a2a8b7bc260560d0c2459ca8aa102596ab282bb094eb690c5ecf767302a8a`
- Remote provider: `ghcr.io/juloc/julos-remote-provider@sha256:e9c9d61adb82e56370a5fdaa76344dab686b4afd90a2ce41fc82cfe3a510b643`

## Security boundary

Unchanged. No Docker socket in Server, immutable digest-pinned runtimes, Runtime Manager as the only Docker control plane, allowlisted runtime networks. No credential, target or trust policy is widened.

## Validation focus

- saving a desktop layout with gapped window z-indexes succeeds and persists a dense stacking order
- a malformed desktop layout returns 400 rather than 500
- a connected interactive session's read returns a revision-bound display descriptor
- the official packages remain byte-identical at `1.0.3`
