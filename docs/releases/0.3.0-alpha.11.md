# JulOS 0.3.0-alpha.11

Release date: 2026-08-08

This alpha repairs the Package Manager HTTP API and the antiforgery/audit correlation-ID handling that every authenticated mutation depends on, found while enrolling a real Agent and installing the official Host Metrics package end to end (AGT-004, AGT-005).

## Fixed

- the antiforgery and Identity session cookies used `CookieSecurePolicy.Always`, which makes ASP.NET Core's antiforgery middleware throw on every request when the connection is not HTTPS; the documented single-container alpha deployment is plain loopback HTTP by design, so every antiforgery-protected mutation (agent enrollment tokens, package install/configure/enable/disable/remove, and more) failed with HTTP 500. Both cookies now use `CookieSecurePolicy.SameAsRequest`, which stays secure whenever the request is actually served over HTTPS;
- `AgentEndpoints` and `PackageCapabilityEndpoints` passed the raw ASP.NET Core `HttpContext.TraceIdentifier` as an audit correlation identifier; its default format contains a colon, which the audit correlation validator rejects, crashing agent enrollment-token creation and package capability invocation with HTTP 500;
- the `core.package.read`/`core.package.manage` authorization policies were referenced by every package endpoint but never registered, so the entire Package Manager HTTP API failed with an authorization-policy-not-found error;
- listing, installing or removing a package whose installation faulted before it wrote its metadata file crashed with an unhandled exception instead of surfacing the row's own fault state;
- extracting a package archive rejected valid ZIP directory entries as path traversal;
- a bad package signature, digest, publisher or manifest crashed the request instead of returning a caller-safe error;
- removing a previously faulted package installation violated a database constraint and crashed;
- `tools/build-package-artifact.sh` could not build the packages it exists for (a UTF-8 BOM and wrong JSON casing broke manifest reading).

## Upgrade from alpha.10

No Core schema change is introduced by this release. Keep the existing `JULOS_PRIMARY_KEY` and persistent volume, pull `ghcr.io/juloc/julos-server:0.3.0-alpha.11`, and recreate the server container.

No database edit or volume recreation is required.

## Docker evaluation

The recommended deployment remains `deploy/alpha/compose.sqlite.yaml`. It runs one JulOS server container with one persistent volume and no PostgreSQL service.

Required environment value:

- `JULOS_PRIMARY_KEY`: generate with `openssl rand -base64 32`.

The release Compose file binds to `127.0.0.1:8080` by default. The `Juloc/docker` deployment uses host port `18199`.

SQLite is intended for one JulOS server replica.
