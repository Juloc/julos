# JulOS 0.4.0-beta.2

Second JulOS beta focused on making the package platform directly testable from the normal JulOS desktop.

## Included

- Adds the Official Package Store to the package manager with Browser, Remote and Host Metrics as first-party packages.
- Official package artifacts are signed with ECDSA P-256 during the release workflow and verified against the embedded official catalog before installation.
- The package signing private key stays in GitHub Actions secrets and is never copied into the server image or release artifacts.
- Official package cards expose install, update, enable, disable and remove actions without asking the operator for manual publisher/signature fields.
- Manual signed third-party package installation remains available under the advanced package flow.
- Existing Browser and Remote Save-as-app/Launch Target persistence is preserved; no parallel favorites model was introduced.
- Browser Runtime remains pinned to `ghcr.io/juloc/julos-browser-runtime@sha256:933a2a8b7bc260560d0c2459ca8aa102596ab282bb094eb690c5ecf767302a8a`.
- Runtime Manager and Remote Provider receive matching `0.4.0-beta.2` release images through the session-runtime publish workflow.

## Security boundary

The JulOS Server does not need and must not receive the Docker socket. Package-owned Browser and Remote containers are created only through the authenticated Runtime Manager. The Runtime Manager is the only JulOS component that requires Docker access.

Remote provider images are accepted by the server policy only as immutable `repository@sha256:...` references. Remote target access remains constrained by explicit network profiles and allowed ports/host patterns.

## Deployment

The beta server image is:

`ghcr.io/juloc/julos-server:0.4.0-beta.2`

The release compose continues to provide the minimal SQLite server profile. The full homelab deployment can add the separately published Runtime Manager and Remote Provider using the same authenticated runtime boundary.

No PostgreSQL service is required for the recommended beta deployment.

## Testing focus

- install/enable/disable/remove/reinstall the official packages from the Package Store
- launch Browser sessions and saved Browser apps through the existing launcher
- exercise SSH/VNC/Remote session flows through Runtime Manager
- verify the server container has no Docker socket while Runtime Manager does

RDP requires a reachable RDP target; absence of such a target is not treated as a successful live RDP validation.
